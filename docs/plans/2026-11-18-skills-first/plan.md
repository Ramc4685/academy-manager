# Skills-first coaching and parent practice history

Implementation brief • November 18, 2026

**Outcome.** On login, a covering coach sees what to teach each proficiency group in the dated class. After class, one report records what actually happened. Each parent sees a dated history of their own child’s practice across batches and progress in every curriculum level.

**Settled rule.** Two children in the same class may practise different skills. A Level 1 child can practise and pass Level 2 skills. Practice goes on the timeline even when completion stays flat. A confirmed pass counts toward the skill’s own level. The placement badge changes only through the Level 1 promotion workflow. Transfers preserve the child’s history.

**Starting point.** Main at c1b5246d6 has daily teaching plans, pass rules and a parent journey. The independent class recap PR #1215 was open at b6fb4a84f when this plan was written. It supplies dated group lessons, per-child practice, report interpretation and owner handoffs. Compare its final merged contracts before integrating. Work on the progress projection and test fixtures can start independently.

## End-to-end release example

A substitute teaches an intermediate overhead clear. Maya, assigned Level 1, practises it and meets the criterion for her third qualifying observation. Leo, assigned Level 2, practises footwork instead. The owner enters the coach’s spoken report after class. After sign-off, Maya’s parent sees overhead clear and a new Level 2 pass. Her Level 2 count moves from 1/4 to 2/4. Her Level 1 count stays 3/5 and her badge remains Level 1. Leo’s timeline contains footwork and he earns no overhead-clear credit. Retry the report, move Maya to Saturday and reopen both timelines. Counts and dates must still agree. For the next lesson the substitute sees drills rotated from each group’s actual delivery.

## Policy choices and operational checks

Proposed defaults for the first release are one quick qualifying observation per child/skill/occurrence, explicit formal reassessment for removing a prior pass, current active curriculum requirements for live percentages, and a separate owner review for a future level already completed. Existing N_TRIES counts qualifying submissions across any days. Changing it to require separate calendar dates is an owner decision. Confirm who may attest a verbally reported lead-only pass. Parent notes appear in-app by default. Confirm delivery channel and cadence before enabling outbound notifications. Built-in recording or cloud transcription would require a separate provider, privacy and retention decision if device dictation is insufficient.

Run focused pytest cases after each slice. Expand integration verification to real Mongo, two-tenant negative tests and a real-auth parent/covering-coach browser journey. Validate migrations, duplicate handling and rollback against the repository runbooks. Run frontend typecheck and relevant Playwright specs, regenerate API types and route inventories for changed routes, and include release notes and sanitized UI evidence. Route PII, authorization and migration changes to the repository’s risk reviewer as well as its reviewer. Roll back new entry surfaces first while retaining recorded history.

**Coding model.** Use Astra with high reasoning for implementation ownership, especially steps 2, 3 and 6. Sol is suitable for narrowly specified UI rendering and fixtures once response contracts are fixed. The runtime report interpreter is a separate product choice evaluated on real coaching language.
