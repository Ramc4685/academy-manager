# Tenant-scope the digest and notice-send mark_* updates; guard-test pattern (#880, #881)

PR: #916

## What changed

- `DigestSendRepository.mark_sent / mark_failed / mark_skipped_empty` (coach and parent digest) and `mark_sent / mark_failed` on the hold, absence and win-back notice-send repos now take `academy_id` explicitly and update by `(academy_id, <id>)` instead of a bare `digest_id` / `send_id`. Call sites pass the academy id they already hold; test fakes mirror the no-match-no-op semantics.
- New migration `0191_drop_digest_send_id_lookup_indexes` removes the two stopgap `*_digest_send_id_lookup` indexes from 0189; the `(academy_id, digest_id)` lookup is served by `*_digest_send_id_per_academy_uq` (added to the real-mongod planner test).
- `scripts/apply_blno_mongo.py` upserts `academy_settings`, `expenses` and `waiver_templates` by `(academy_id, <id>)` and uses the real `waiver_template_id` field; `scripts/import_blno.py` is marked historical single-tenant and now enforces it at runtime: `main()` refuses to run unless `BLNO_IMPORT_SINGLE_TENANT_ACK=1` is set and the DB has exactly one `academies` row, and its `expenses` inserts carry that `academy_id` plus an `expense_id`. The password fail-fast moved from import time into `main()` (same CLI behaviour).
- `test_no_raw_tenant_mongo_access` now flags unscoped mutating calls on a repository's own `self.collection`, and registers `lesson_cards`, `curriculum_video_refs`, `coach_digest_sends`, `parent_digest_sends` as tenant-owned. Pattern documented in `docs/agent/backend-api-rules.md`.

## Deploy notes

- Deploy the code first. Then apply migration 0191 by hand (production applies migrations manually): `coach_digest_sends.coach_digest_send_id_lookup` and `parent_digest_sends.parent_digest_send_id_lookup` are dropped. 0191 is idempotent and is a no-op on a database where 0189 has not run.
- Do not apply 0191 before the code is live: the old bare-`digest_id` update would become unindexed on those two collections.
- No frontend change, no route change, no data backfill.

## Risk / rollback

- Behaviour change is limited to the update filter shape on six repositories; claim / retry / reclaim logic in `digest_claim.py` is untouched. With one academy the filter always matches the same row it did before.
- Rollback: revert the PR. If 0191 was already applied, recreate the plain indexes with `db.coach_digest_sends.createIndex({digest_id: 1}, {name: "coach_digest_send_id_lookup"})` and the parent equivalent so the reverted bare-id update stays indexed.
- The guard-test extension is a static test only; it cannot affect runtime.
