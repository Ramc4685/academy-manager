# parent-dropoff-checkin

PR: #1231

## What changed
Academies can switch on parent drop-off check-in under Settings → Family policies → "What parents can do in the app". It is off by default, and the window opens 0–60 minutes before class (default 30) and closes 0–240 minutes after the start (default 15). When it is on, a parent's class row on My children shows "I've arrived" only while the window is open, and a class that already started stays listed through the window (and an hour after) so it is still reachable. After the tap it reads "Arrival sent · Waiting for staff", and once the child has a Present (or Late) mark it reads "Checked in", whether staff tapped Confirm or marked attendance by hand. A report nobody confirmed reads "Arrival not confirmed · Please tell a coach in person" after the window closes. All of these come from the server, so they survive a refresh, and the page refreshes itself while a window is open. Each sibling is checked in on their own. If the phone is offline or the request fails, the row says staff have NOT received the arrival and offers Retry. The request is never queued or replayed later. On the coach class screen, a reported child shows "Arrived · Awaiting confirmation" with a one-tap "Confirm drop-off", and manual marking is unchanged. The coach roster refreshes itself while the class's window is open. If the child already has an Absent or voided mark, Confirm is refused with a message to correct the mark to Present instead of showing "Checked in". The admin class-date Attendance dialog (admins only) adds an Expected / Arrived / Checked in breakdown, a "Confirm drop-off" button and "Reported by X at T · Confirmed by Y at T" in academy time. The dialog is also offered around class time before any mark exists. A parent's report is never attendance: only the staff confirmation writes the Present mark, through the existing attendance path, and it links to an existing Present/Late mark instead of writing a second one. A report nobody confirmed expires when the window closes and never counts. A drop-off report also keeps its class date from being deleted when the class time or weekday is edited (it is soft-cancelled instead).

## Deploy notes
Migration `0246_dropoff_checkins` adds the `dropoff_checkins` collection with a unique `(academy_id, occurrence_id, student_id)` index and is applied by the release command. There are no new env vars. The new policy fields default to off, so no academy sees a change until an admin enables it. New endpoints: parent `POST /parent/children/{student_id}/occurrences/{occurrence_id}/arrival`, coach `POST /coach/occurrences/{id}/checkins/{student_id}/confirm`, and admin `POST /admin/session-occurrences/{id}/checkins/{student_id}/confirm`. The parent schedule, coach today (now with the session's drop-off window) and admin attendance reads gain additive fields, which older cached PWA clients ignore.

## Risk / rollback
Confirmation writes attendance, and attendance feeds payroll and make-ups. It reuses MarkAttendance with a deterministic id, so concurrent or repeated confirms converge on one mark. To stop the feature, switch it off per academy: reports already pending stay unconfirmed and never count. To remove it entirely, revert the PR. The collection can stay, because nothing else reads it.
