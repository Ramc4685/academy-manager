# batch-3c-core-lifecycle-admin

PR: #0

## What changed

- Fixes #782 — Three orphan bugs in enrollment lifecycle handling, each pinned by a test written failing-first before the fix.
- Fixes #783 — Schedule edits no longer orphan occurrence dependents: the admin cascade's clean-occurrence check now consults all eight collections that pin an `occurrence_id` (previously only `attendance`/`coach_attendance`/`payout_period_lines`), via a new `occurrence_dependents.py` map in enrollment infrastructure. This moved out of `composition/admin.py` because that file sits on a hard 4500-line wiring budget — it now lands at 4496.
- Fixes #785 — Disabling a staff/parent account is no longer a no-op for auth: `MongoUserRepository._to_domain` now maps the stored `users.status` onto `User.global_status` (which previously defaulted to "active" regardless of the stored status, so `LoadAuthClaims._user_is_active`'s primary check never saw the disable and the legacy `is_active` fallback was never reached). A disabled account now actually loses login and stops being billed; a doc with neither `status` nor `is_active` still defaults to active so no existing account gets locked out by this change.
- Fixes #775 — `GetLeavingReport`'s `DEPARTURE_EVENT_TYPES` now includes `"cancelled"`, which is what a parent self-cancel and a processed scheduled cancellation actually record. Previously those families had no Left row and were invisible to the report, with no path to re-enroll from it. (`"removed"` was already present, so #744 was already fixed.)
- Fixes #784 — Voiding an invoice now unwinds the credit it consumed (previously the account credit stayed decremented forever, spent on an invoice that no longer owes anything, with `applied_invoice_ids` still pointing at the voided invoice) and closes out any `stripe_invoice_id`-linked invoice in Stripe (previously it stayed open and collectible). Both void paths now write the `invoice_voided` audit row the action already declared but never emitted.
- Fixes #787 — Payout period freeze is now enforced upstream: marking coach attendance (status/rate_override) and cancelling a dated class ask finance whether an approved or paid payout period already covers the date, and refuse with a 409 (`Coaching.PayoutPeriodFrozen` / `Enrollment.PayoutPeriodFrozen`) instead of silently editing a snapshot nobody re-reads. Each context declares its own one-method `PayoutPeriodLock` port; one composition adapter (`PayoutInputLock`) translates it into a finance read, so no cross-context import was introduced.
- Fixes #778 — Adds the win-back slice: a daily `SendWinBackNotices` job emails a departed student's family at 30/60/90 days after their "dropped" lifecycle event. Idempotent per (student, milestone) via the existing `claim_digest_send` pattern; cancelled by re-enrollment (any current active/held enrollment skips remaining milestones, no claim written); suppressed (not deferred) when the family has an open/partially-paid invoice with balance owing — a default the commit calls out explicitly rather than a settled product decision. Registered in `SCHEDULED_JOB_MONITORS`/`JOB_STALE_AFTER` so it's covered by `sentry_cron_jobs` like every other scheduled job. Out of scope: waitlist copy, pre-cancellation reminder, suppression-list frontend, student timeline tab, parent notification-preferences page.
- Fixes #776 — Merges Admissions + Requests into one `/admin/inbox` route: `GET /admin/inbox/counts` fans out to the same use cases backing each queue, every tab shows its pending count, and the first non-empty queue opens by default (`?tab=` always wins when present). Old routes redirect with the tab preserved; nav, screen-meta, route manifest, and route-count assertions all updated. Pending registrations now appear in the home attention lane, linking into the matching Inbox tab.
- Fixes #774 — Adds a daily `send_past_due_reminders` scheduler job emailing parents at due+N days (offsets, default 15/20, editable in Settings > Billing rules; an empty list is the off switch). Runs hourly but only fires for an academy whose local hour is 9am, idempotent per (invoice, offset) via a `reminder_sent_days` stamp, and deliberately does not filter on `enrollment_id` so manual/Mode-B invoices are chased too. Reuses #795's naming helpers so the email names the month and student instead of a raw period code. Registered in `settings.sentry_cron_jobs` and the ops stale-job table. Admin home gains two attention cards (autopay failure, dunning exhaustion); Collections' `last_reminder_at` now reflects automated sends too. Coaches now see exactly one money fact — a PAYMENT DUE chip on an overdue roster row — and the coach billing-preview drawer, its toggle, and the coach `billing-enrollments` routes are removed, along with the dead `dues_reminders`/`attendance_alerts` notify toggles (superseded by Billing rules).
- Fixes #777 — Coach Today and the session header show "n/N marked" plus a Needs-marks badge instead of a bare student count, and Today gets a "Recent, not fully marked" 48h section built from the two preceding days' `/coach/today` reads.

## Deploy notes

No new migrations in this lane. `PayoutInputLock` (#787) and `occurrence_dependents.py` (#783) are pure application/infrastructure wiring with no schema change. The win-back job (#778) and the past-due reminders job (#774) are new scheduled jobs — confirm both are picked up by whatever process registers `sentry_cron_jobs` monitors at deploy, and that the scheduler process itself gets restarted so the new jobs are scheduled.

## Risk / rollback

Highest-risk items touch money and access: #784 (invoice void unwinding credit + closing Stripe invoices), #787 (payout freeze enforcement, a new 409 that could surprise an existing caller who edited attendance/cancellations post-freeze), and #785 (auth now actually respects a disabled account — a behavior change for any account that was silently disabled-but-still-active before). Each ships with a test written failing-first pinning the fix. If anything regresses in prod, revert this PR's merge commit; no destructive data migrations are included, so a revert is a clean rollback.
