# Public academy page on the tenant host: server-rendered `/`, metadata, JSON-LD, OG card, robots and sitemap (Lane B3)

PR: #937

## What changed

- **Route decision.** The public academy page is the root path `/`, made host-aware rather than added as a new route. `frontend/app/page.tsx` now dispatches on the request host: a product host (`academy.courtmastr.com`, `courtmastr.com`, `www.courtmastr.com`, overridable with `PUBLIC_PAGE_PLATFORM_HOSTS`) keeps the existing CourtMastr landing page, unchanged and without calling the backend (the landing JSX moved verbatim to `frontend/components/marketing/PlatformLandingPage.tsx`). Every other host is a tenant host and renders that academy's page from `GET /api/v2/public/academy`. A frontend host list is needed because production runs `APP_TENANCY_MODE=single_academy`, where the backend resolves every allowed host to the one live academy, so "ask the API" alone cannot tell the product host apart. `frontend/middleware.ts` only matches the persona prefixes (`/admin`, `/coach`, `/parent`, `/platform`), so `/` is never touched by the persona gate: signed-in users keep their routing and the auth redirects are unchanged. `/login` and `/register` stay under `(marketing)` on the same host.
- **Server fetch.** `frontend/lib/public-page/server-fetch.ts` calls the backend directly from the server (one read per request via React `cache`, shared by the page and `generateMetadata`). It forwards only Host (as `x-forwarded-host`), `CF-Connecting-IP`, user agent, language and request id through the existing `buildProxyHeaders`, which stamps the `x-cm-proxy-auth` secret so the backend rate limit is per visitor. Cookies and bearer tokens are never forwarded: the read is anonymous even for a signed-in visitor. `cache: "no-store"` because the backend URL is identical for every host; the backend's 60s `Vary: Host` cache is the only cache.
- **Page.** Hero with "Book a free trial" as the primary action (anchor `#trial`; the trial section is a placeholder the B4 form fills), programs with class rows (when, ages, level, where, price as amount plus period, seat band "Open" / "N spots left" / "Full, join waitlist" with a "Join waitlist" action instead of "Register"), coaches (the name string exactly as the backend resolved it for `coach_display`), venue with address, hours and a maps link, FAQ (static phase-1 copy built from the page flags; B2's DTO has no FAQ field), and the fixed "Bookings and payments by CourtMastr" footer credit. Brand buttons use `brand_fill` and `brand_on_color` from the backend colour function; no colour is derived in TypeScript.
- **States.** Loading (Suspense fallback), published, nothing published yet (page unpublished: branding and Parent login only; or published with no classes: "timetable on its way" notice), trials closed (`page.trials_open=false`: trial actions swap for open classes and Register, "first class free" removed), every class full, unknown host (backend 404 -> `notFound()`), and backend unavailable (plain retry notice, never a blank page).
- **SEO.** Per-tenant `generateMetadata` (title, description, canonical, Open Graph, Twitter card, `noindex` for unpublished and empty states), JSON-LD `SportsActivityLocation` with academy name, address, logo and URL only (no coach or personal data), a generated 1200x630 OG card at `/og-card` (`next/og` `ImageResponse`), and per-host `/robots.txt` and `/sitemap.xml` route handlers (root only; class pages are phase 2).
- **Accessibility.** One header, main and footer landmark, h1 then h2 per section, visible focus rings, motion only under `prefers-reduced-motion: no-preference`, dark-scheme support.
- **Route checklist.** `/og-card`, `/robots.txt` and `/sitemap.xml` added to `docs/qa/2026-06-28-production-scale-local-inventory-manifest.json`; the `/` entry gains the tenant workflows, states and risks. Route counts bumped 92 -> 95 in `test_inventory_control_evidence.py` and `test_inventory_acceptance_coverage.py`. The three non-HTML handlers are excluded from the local-auth "renders meaningful content" sweep.
- **Tests.** Vitest for formatting (price, period, seat bands, age bands, days, truncation), host handling, page model, metadata, JSON-LD, robots/sitemap and forwarded headers. Playwright `public-tenant-page.spec.ts` covers every state, metadata and JSON-LD, the OG card, robots and sitemap, and asserts the server read carries the host and proxy secret but no cookie or authorization. Because the page is server-rendered, browser-side `page.route` cannot stub it: `playwright.config.ts` now starts a tiny stub backend (`e2e/fixtures/public-academy-stub.mjs`, fixtures chosen by user agent) and points the Next dev server's `BFF_API_ORIGIN` at it. Every other path the stub receives answers 502, like the dead backend it replaces; all other specs stub in the browser and are unaffected. Fixtures use a fictional academy.

## Deploy notes

- No migration. No backend change.
- The frontend worker needs `BFF_PROXY_SHARED_SECRET` (already set for the BFF proxy) so the backend trusts the forwarded `CF-Connecting-IP`; without it the rate limit keys on the worker's address.
- Optional `PUBLIC_PAGE_PLATFORM_HOSTS` (comma separated) replaces the default product-host list; leave unset in production.
- Nothing is visible to the public until an owner publishes the page (B1 default `public_page.published=false`); until then the live academy's tenant host shows the branding-only "not taking new players" state with `noindex`. `academy.courtmastr.com/` keeps the product landing page.
- Build stays `next build --webpack`.

## Risk / rollback

- Medium-low: `/` on a non-product host now renders the academy page instead of the product landing page. A host missing from the product-host list would show a tenant page (or the 404) instead of the landing page; fix by setting `PUBLIC_PAGE_PLATFORM_HOSTS`.
- A backend outage on a tenant host shows the retry notice, not the landing page.
- Rollback: revert the PR. No data or schema to undo.
