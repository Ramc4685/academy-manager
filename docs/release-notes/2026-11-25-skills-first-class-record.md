# skills-first-class-record

PR: #1242

## What changed
Steps 3 to 6 of the skills-first plan, shipped together.

**Recoverable class passes.** A class recap saves each child's skill passes along with the taught skills and practice, and each pass counts once per class, child and skill. Retrying a save, two coaches saving at once, or a save that stopped part way all end with one test attempt, one N_TRIES try and one `SkillPassed` event. A pass that is still finishing shows "Pass still saving", and any later save completes it. A counted pass cannot be removed by editing the recap; that needs a formal reassessment. A pass the skill rules never counted can be taken off. A coach's take-back, or a failed formal test that demotes a pass, closes any unfinished class pass so no later save restores it. An N_TRIES skill shows "Counted as a try" until its Nth try. The step-2 `POST .../class-demonstrations` route is replaced by `passes` on `PUT .../class-recap`.

**Parent class timeline.** A child's progress page now opens with their class timeline, newest first, ahead of current level progress. Each class shows its date, the class lesson, what this child practised, and "Passed at this class" only on the class whose demonstration earned a pass that still stands. A practice repeated across classes shows on every date. A group lesson never claims the child practised. "Show older classes" loads a page at a time with a stable order across batches. Current mastery stays in the level section. Coach report text and other children never appear.

**Teaching assignment on Coach Today.** The teaching plan picks each level group's drill from what this batch did in earlier classes. Each group shows the cue, how many of its children the drill is for, and when the group last worked on it, or "No delivery history yet for this group". A drill that only repeats the last lesson is skipped unless nothing else is for anyone in the group; then the plan repeats one on purpose and says so. Children the drill does not cover are listed as variations, and a group above the first level gets a warm-up from the level below. History is per batch, so a substitute sees the same rotation. The same inputs always give the same plan. Dates show in the session timezone, and the admin occurrence plan reads history up to that class. The recap gains "What each group worked on", which the lead coach or owner ticks per level group.

**After-class report into the same record.** When AI reads a report, each level group's lesson now gains the skills its own children practised, so the next plan rotates from a spoken report as it does from a typed recap. Teaching alone credits no group. A pass the report mentions is still never recorded by the report: the lead coach or owner can now tap "Add pass" on it, and saving the recap runs it through the same pass rules as a tapped pass.

## Deploy notes
Two migrations apply through the usual release command. `0247_test_attempts_observation_key` adds a partial unique index on `test_attempts (academy_id, observation_key)`, covering only rows with a key, so it builds without conflicts. `0248_class_recaps_session_index` adds `class_recaps_session_idx` on `class_recaps (academy_id, session_id, class_starts_at desc)`. Both are index-only, need no backfill, and re-run as no-ops. Outbox appends with a duplicate `event_id` are treated as already queued. Deploy backend and frontend together: a new frontend on an old backend would have its passes ignored.

## Risk / rollback
If an index build fails, the deploy stops before new code serves traffic; rerun after checking for duplicate keys, of which there should be none. Passes recorded before this release never show as "Passed at this class" on older dates. Recaps saved before this release have no group lessons, so every group starts with "No delivery history yet". Recaps are now filed under a term clone's template batch, which the plan reads. Children not placed on a level form no group, and an academy with more than one active program gets no groups. Hands-free dictation is not promised: coaches type, or use their keyboard's own dictation, into the report box. Roll back by reverting this PR: older code ignores the new fields, recorded history stays, and the indexes are inert without the new code. Unmarking an off-level class pass is still not possible.
