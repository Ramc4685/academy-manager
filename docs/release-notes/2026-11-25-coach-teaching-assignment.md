## What changed
Coach Today's teaching plan now picks each level group's drill from what this batch actually did in earlier classes, instead of always showing the first matching lesson card. For each group it shows the cue to say out loud, how many of the group's children the drill is for, and when the group last worked on it. A group with no recorded history says "No delivery history yet for this group". A drill that only repeats the last lesson's skills is skipped, unless no other drill is for anyone in the group: then the plan repeats one on purpose and says so. Children whose own next skill the drill does not cover are listed as variations. A group above the first level also gets a warm-up drill from the level below. History is per batch, not per coach, so a substitute sees the same rotation, and one group's lesson never rules out another group's drill. The same inputs always give the same plan. Class dates show in the session's timezone, and the admin occurrence plan reads history up to that class, not up to now. The class recap gains "What each group worked on": the lead coach or owner ticks, for each level group in the class, which taught skills that group worked on. That record feeds the next class's plan. `GET`/`PUT /coach/occurrences/{id}/class-recap` return `groups` and `group_lessons`, and the save accepts an optional `group_lessons` (omitted keeps the recorded ones).

## Deploy notes
Migration `0248_class_recaps_session_index` adds the index `class_recaps_session_idx` on `class_recaps (academy_id, session_id, class_starts_at desc)` for the plan's per-batch history read. It is index-only, needs no backfill, and re-running it is a no-op. It applies through the usual release command. Deploy backend and frontend together as usual.

## Risk / rollback
Recaps saved before this release have no group lessons, so every group starts with "No delivery history yet" until coaches record a class. Until then the plan ranks drills by how many children need them, then catalog order. Children not placed on a level form no group in the recap, and an academy with more than one active program gets no groups, so the section does not appear there. Recaps are now filed under a term clone's template batch, which is the batch the plan reads. Roll back by reverting this PR: older code ignores the new recap field, and the extra index is harmless to leave in place.
