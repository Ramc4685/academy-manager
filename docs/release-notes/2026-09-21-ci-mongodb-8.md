# ci-mongodb-8

PR: #TBD

## What changed

- CI now tests against MongoDB 8.0, the version production runs, instead of 7.0. Both places are updated: the `mongo` service container used by the backend job, and the native `mongod` installed for the real-auth end-to-end job (now from MongoDB's official Ubuntu 24.04 repository, which 7.0 did not have).
- Why: the two versions choose query plans differently. In #878 a lookup was served from an index on 7.0 and scanned the whole collection on production's 8.0, and nothing in CI could have shown it. This is the first step of #894; the planner check itself follows separately.
- No application code changes.

## Deploy notes

None. CI-only. Nothing to apply in production, no env vars.

## Risk / rollback

Low. If the suite or the end-to-end job misbehaves on 8.0, revert this PR's merge commit to return CI to 7.0. Local development and the Docker Compose stacks are untouched and still use whatever MongoDB is installed locally (`docker-compose.yml` stays on `mongo:7`: moving it would upgrade developers' existing data volumes one-way, so that is left as a separate, deliberate step).
