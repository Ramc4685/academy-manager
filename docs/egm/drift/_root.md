- [undocumented] README.md:89-102 (Deployment pipeline) lists seven steps, but `.github/workflows/production.yml` also runs a `sentry-release` job (`production.yml:1053`, after `smoke`) in parallel with `publish-release` (`production.yml:1123`). The README does not mention it.
- [wording] README.md:92-93 says Validate covers "backend compile/tests, v2 DDD boundary checks, and Next.js typecheck/lint/build/E2E". The workflow also runs real-Mongo contract tests (`production.yml:167`), ruff/mypy (`production.yml:260-274`), a dependency advisory job (`production.yml:229`), an OpenAPI drift check (`production.yml:312`), a scripts job (`production.yml:673`) and hook tests (`production.yml:718`). The summary is incomplete, not wrong.
- [wording] README.md:98 says backend deploy is `flyctl deploy --remote-only --app courtmastr-academy-api`; the actual command is `flyctl deploy --image <migrate-production image> --release-command-timeout 25m --ha=false --app courtmastr-academy-api` (`production.yml:961-963`); the image is built earlier in `migrate-production` (`production.yml:820`).
- [wording] README.md:51 calls the service "managed, multi-region"; the API is a single Fly machine in one region (`backend/fly.toml:2` `primary_region = "ord"`, `--ha=false` at `production.yml:963`).
