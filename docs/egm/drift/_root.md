- [wording] README.md:98 gives the backend deploy as `flyctl deploy --remote-only --app courtmastr-academy-api`. `.github/workflows/production.yml:963-966` runs `flyctl deploy --image <prebuilt migrate-production image> --release-command-timeout 25m --ha=false --app courtmastr-academy-api --env SENTRY_RELEASE=...`. The image is built in the migration job (`production.yml:822`), not by the deploy command.
- [undocumented] README.md:100-102 ends the pipeline at "Release record". `production.yml:1057` defines a `sentry-release` job (needs `smoke`) that runs alongside `publish-release` (`production.yml:1127`).
- [undocumented] README.md:92-94 lists Validate as compile/tests, boundary checks and Next.js checks only. `production.yml` also runs a real-Mongo contract job (`:167`), dependency vulnerability scans (`:143`, `:308`), an OpenAPI drift check (`:312`), a Worker runtime smoke, a scripts job (`:675`) and hook classifier tests (`:720`), all gated by `ci-gate` (`:735`).
- [wording] README.md:101-102 says the release record is published "only when every changed component deployed and smoke passed". `production.yml:1127-1132` gates `publish-release` only on `needs: [smoke]` (plus an `if:`). The per-component check is not in the workflow.
- [wording] README.md:116-117 says email verification is enforced "at every authenticated request". It lives in `backend/v2/contexts/identity/application/token_claims.py`, and a per-request call site was not traced.
- [contract] README.md:139 gives a `SECURITY DISCLOSURE` subject line for the security contact. `SECURITY.md:6` directs reporters to GitHub "Security -> Report a vulnerability" and has no email or subject line.
