## frontend/lib/api/README.md

- [stale-not-built] README:13-14 says `generated/` "currently contains only `.gitkeep`; no OpenAPI snapshot or generated `v2.d.ts` is committed". Code: `frontend/lib/api/generated/v2.d.ts` exists (about 1 MB) and `frontend/lib/api/openapi.snapshot.json` exists (about 1.4 MB). There is no `.gitkeep`.
- [stale-not-built] README:30-31 says "When generated types are reintroduced, commit the resulting `generated/v2.d.ts`". They are already committed and are the active contract (`frontend/lib/api/generated/v2.d.ts:1`).
- [contract] README:16-28 says types are regenerated from a running FastAPI app (uvicorn on port 8001, then `pnpm generate:api`). `frontend/package.json:16` runs `openapi-typescript lib/api/openapi.snapshot.json -o lib/api/generated/v2.d.ts`. It reads the committed snapshot and does not need a running backend. The snapshot itself is kept in sync by a backend structural test (`.github/workflows/production.yml:313`), which the README does not mention.
- [contract] README:35-39 says CI runs the OpenAPI drift check only when `openapi.snapshot.json` exists, and otherwise prints "No openapi.snapshot.json yet. Skipping drift check.". `.github/workflows/production.yml:312-321` runs the check unconditionally. It regenerates types from the snapshot, diffs them against `lib/api/generated/v2.d.ts`, and fails the build on any difference. There is no skip message. The README's claim that CI "relies on the hand-written typed client modules plus their focused tests" is also wrong.
- [undocumented] README:7-9 lists only a subset of the top-level modules. These are in `frontend/lib/api/` but not in the README:
  - API wrappers: `admin-account-deletions.ts`, `admin-ai-import.ts`, `admin-crm-pipeline.ts`, `admin-families.ts`, `admin-family-contacts.ts`, `admin-family-crm.ts`, `admin-family-import.ts`, `admin-people-duplicates.ts`, `billing-contract.ts`, `magic-link.ts`, `parent-home.ts`, `platform.ts`, `student.ts`, `unsubscribe.ts`.
  - Auth and proxy helpers: `auth-bridge-cookie.ts`, `auth-token.ts`, `coach-paths.ts`, `payment-error.ts`, `proxy-headers.ts`, `proxy-origin.ts`.
  - Test files: `*.test.ts`, `*.node-test.mjs`.
- [undocumented] README:11-12 describes `v2/` as "memberships, payouts, payroll, sessions, and students". `frontend/lib/api/v2/` also holds `announcements.ts`, `departure-policy.ts`, `messages.ts`, `owner.ts`, `pricing.ts`, `session-types.ts`, and a `README.md` of its own.
- [wording] README:7 says `client.ts` provides "in-flight dedup" without qualification. `frontend/lib/api/client.ts:195` dedups only when `dedup` is true or the request is readable (`dedup ?? isReadable`). The client also takes `timeoutMs` (default 20s) and `authToken` options (`client.ts:168-172`), which the README omits.
