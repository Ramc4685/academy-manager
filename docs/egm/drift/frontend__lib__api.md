## frontend/lib/api/README.md

- [stale-not-built] README:13-14 says `generated/` "currently contains only `.gitkeep`; no OpenAPI snapshot or generated `v2.d.ts` is committed". Code: `frontend/lib/api/generated/v2.d.ts:1` and `frontend/lib/api/openapi.snapshot.json:1` are both tracked in git. There is no `.gitkeep` in `generated/`.
- [stale-not-built] README:30-31 says "When generated types are reintroduced, commit the resulting `generated/v2.d.ts`". The types are already committed and are the active contract (`frontend/lib/api/generated/v2.d.ts:1`).
- [contract] README:18-28 says types are regenerated from a running FastAPI app (uvicorn on port 8001, then `pnpm generate:api`). `frontend/package.json:16` runs `openapi-typescript lib/api/openapi.snapshot.json -o lib/api/generated/v2.d.ts`. It reads the committed snapshot and needs no running backend. The README does not say how the snapshot is kept current: a backend structural test does it (`.github/workflows/production.yml:313-314`).
- [contract] README:35-39 says CI runs the OpenAPI drift check only when `openapi.snapshot.json` exists, otherwise prints "No openapi.snapshot.json yet. Skipping drift check.". `.github/workflows/production.yml:312-321` runs the check unconditionally. It regenerates types from the snapshot, diffs against `lib/api/generated/v2.d.ts`, and fails with "lib/api/generated/v2.d.ts is out of date". There is no skip path. The claim that CI relies only on hand-written client modules is also wrong.
- [undocumented] README:7-10 does not list many top-level modules in `frontend/lib/api/`: `admin-account-deletions.ts`, `admin-ai-import.ts`, `admin-crm-pipeline.ts`, `admin-families.ts`, `admin-family-contacts.ts`, `admin-family-crm.ts`, `admin-family-import.ts`, `admin-people-duplicates.ts`, `billing-contract.ts`, `magic-link.ts`, `parent-home.ts`, `platform.ts`, `student.ts`, `unsubscribe.ts`, and the helpers `auth-bridge-cookie.ts`, `auth-token.ts`, `coach-paths.ts`, `payment-error.ts`, `proxy-headers.ts`, `proxy-origin.ts`.
- [undocumented] README:11-12 describes `v2/` as "memberships, payouts, payroll, sessions, and students". `frontend/lib/api/v2/` also holds `announcements.ts`, `departure-policy.ts`, `messages.ts`, `owner.ts`, `pricing.ts`, `session-types.ts`, and its own `README.md`.
- [undocumented] README:8-10 calls `admin.ts` a "thin typed wrapper". `chargeAdminInvoiceAutopay` (`frontend/lib/api/admin.ts:2866-2900`, uncommitted) now holds client-side state: a module-level `unconfirmedCharges` map and a 10-minute `CHARGE_RETRY_WINDOW_MS`. It reuses the same `request_id` for retries after unconfirmed outcomes (timeout, 5xx, 409) and clears it on other 4xx. Related autopay types were also added: `AdminAttentionKind` gains `"autopay_stuck"` (`admin.ts:1375`), and `ConnectReadiness` gains `payments_blocked_reason`, `disputes` and `refund_failures` (`admin.ts:2418-2430`), with `RefundFailure(s)` and `OpenDispute(s)` at `admin.ts:2433-2463`.
- [wording] README:7 says `client.ts` provides "in-flight dedup" without qualification. `frontend/lib/api/client.ts:195-196` dedups only when `dedup` is true or the request is a GET/undefined method (`dedup ?? isReadable`). `apiFetch` also takes `timeoutMs` (default 20s) and `authToken` options (`client.ts:168-172`), which the README omits.
