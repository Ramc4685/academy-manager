- [stale-not-built] README:3 links the migration plan at `../../../.claude/plans/write-a-detailed-plan-curried-trinket.md`. That path does not resolve from `backend/v2` (no `.claude/plans` directory in the repo or worktree).
- [stale-not-built] README:29 says `tests/structural/` has "event-rules checks". `backend/v2/tests/structural/` has layering, wiring, persona-gate and mirror tests, but no event-rules test (no file named for events; `test_layering.py` is the only rule check).
- [undocumented] README:10-31 Layout omits `composition/` (about 100 wiring modules, `backend/v2/composition/*.py`). README:30 and README:53 say `main.py` is the composition root and that step 8 wires a context "in `main.py`". Real wiring lives in `composition/<context>.py` and is called from `main.py`. `backend/pyproject.toml:182` adds an import-linter contract `composition-is-outermost`, which README:33-42 does not list.
- [undocumented] README:13 and README:59 name only the admin, coach, parent and platform personas. `backend/v2/interfaces/` also has `owner/` (`router.py`), `student/`, `public/`, plus top-level route modules (`me_routes.py`, `registration_routes.py`, `magic_link_routes.py`, `password_reset_routes.py`, `unsubscribe_routes.py`, `email_webhook_routes.py`). `owner/` has no `views.py`, so README:63 "return a view DTO from `interfaces/<persona>/views.py`" does not hold for every persona.
- [undocumented] README:93-94 and README:5-6 say all routes are mounted under `/api/v2/*`. In `main.py:3024-3035` the platform, student and owner routers are mounted only when `enable_platform_routes`, `enable_student_login` or `enable_owner_role` is set. Otherwise they return a true 404.
- [undocumented] README:14-21 `shared/` lists 7 packages. The code also has `comms/`, `profile/`, `scheduling/`, `security/`, `time/`, and modules `caching.py`, `ids.py`, `money.py`, `names.py` and `occurrences.py`.
- [undocumented] README:24-29 `tests/` omits `composition/`, `contexts/`, `infrastructure/`, `shared/`, `fixtures/`, `seed/` and root-level tests such as `test_no_raw_tenant_mongo_access.py`.
- [wording] README:27 says contract tests use "mongo + stripe via testcontainers". No `testcontainers` reference exists under `backend/v2/tests` (`grep` found none).
- [contract] README:101 says mypy is "advisory". `.github/workflows/production.yml:268-274` runs `mypy -p backend.v2` piped through `mypy-baseline filter`. New errors fail the build, and only pre-existing errors are frozen in `backend/mypy-baseline.txt`. The README's command (`mypy ... v2`) also differs.
- [contract] README:103 says pytest requires "≥70% coverage on `v2/shared`". `production.yml:165` runs `--cov=v2 --cov-fail-under=86`, which covers all of v2 at a floor of 86%.
- [undocumented] README:46-49 describes contexts as `{domain,application,infrastructure}`. Some contexts have extra pieces: `contexts/platform/` has nested `audit/`, `billing/`, `governance/` (the import-linter contracts use `contexts.*.*` patterns for them), and `contexts/curriculum/content/` also exists. Contexts `crm`, `ai`, `onboarding` and `platform` have their own READMEs, which is fine.
