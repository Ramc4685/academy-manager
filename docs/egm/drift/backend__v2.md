- [undocumented] README:18 describes `shared/idempotency/` as "@idempotent decorator + Mongo store". Working-tree changes in `shared/idempotency/decorator.py` add a claim/release protocol (`IdempotencyStore.claim`/`release`, a `<key>:claim` entry) and a new `IdempotentRequestInFlight` error (HTTP 409, code `request_in_flight`), exported from `shared/idempotency/__init__.py`. Concurrent first calls now get 409. The claim is also released if the result write (`store.put`) fails, so a retry re-runs. `mongo_store.py:11-60` implements it, and takes over a claim older than `CLAIM_STALE_AFTER` (a request that died mid-flight) atomically instead of waiting out the 7-day TTL. None of this is in the README. (Updated: stale-claim takeover is NEW.)
- [undocumented] NEW: README:14 (`shared/events/` "outbox + dispatcher") omits the failure-reporting behavior now in `shared/events/dispatcher.py:134-152` (working tree). Loop failures are logged as a throttled warning and sent to Sentry via `capture_exception` only when `should_report_failure` allows it.
- [undocumented] NEW: README:22 and :52 ("Add a migration for indexes in `migrations/`") do not mention the uncommitted `migrations/0240_audit_logs_audit_id_unique.py`, which adds a unique partial index (`academy_audit_id_unique`) on `audit_logs.audit_id` and fails with a named duplicate list if existing rows collide.
