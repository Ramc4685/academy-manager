## backend/v2/README.md

The README does not mention billing, autopay, dunning, webhooks, receipts, reminders, card-on-file or dashboard attention items. The uncommitted billing/autopay changes in this worktree therefore add no drift against it beyond the undocumented items below.

- [stale-not-built] README:3 links `../../../.claude/plans/write-a-detailed-plan-curried-trinket.md`. That path does not exist in the repo or worktree. The plan is only in the user's home directory.
- [contract] README:27 says `contract/` is "mongo + stripe via testcontainers". `testcontainers` appears nowhere under `backend/v2` or in `backend/requirements*.txt`. CI runs the contract tier against a native mongod (`.github/workflows/production.yml`, job `backend-contract-real-mongo`). Stripe fixtures are static (`backend/v2/tests/contract/stripe_fixtures`).
- [contract] README:42 refers to "the six layer rules" enforced by import-linter (README:33). `backend/pyproject.toml:83-186` does define six contracts: domain-is-pure, application-does-not-import-infrastructure, infrastructure-does-not-import-interfaces, interfaces-do-not-import-infrastructure-or-domain-directly, invoicing-core-independent-of-academy-pricing and composition-is-outermost. These are not the ADR-0005 six. The ADR's no-cross-context and tenancy-literal rules are enforced by pytest structural tests (`backend/v2/tests/structural`, `backend/v2/tests/test_no_raw_tenant_mongo_access.py`).
- [contract] README:101 says `mypy --config-file backend/pyproject.toml v2` is "advisory". CI runs `mypy --config-file backend/pyproject.toml -p backend.v2` filtered through `backend/mypy-baseline.txt`, so new errors fail the build (`production.yml:268-274`).
- [contract] README:103 says "≥70% coverage on `v2/shared`". CI enforces `--cov=v2 ... --cov-fail-under=86` over all of v2 (`production.yml:165`).
- [contract] README:102 says import-linter checks "layer rules + tenancy". `backend/pyproject.toml` has no tenancy contract. The CI step is only `lint-imports --config pyproject.toml` (`production.yml:159`).
- [undocumented] README:11-30 and the diagram at README:35-40 omit `backend/v2/composition/` (90 wiring modules). It is the outermost layer (`backend/pyproject.toml:181-186`). README:53 says to wire a context in `main.py`, but wiring lives in `composition/*.py`. Many of the modified files in this worktree are there (`composition/admin.py`, `billing_health.py`, `collections.py`, `dues_reminders.py`, `email_adapters.py`, `event_handlers.py`).
- [undocumented] README:13 and README:59 list interfaces/personas as admin, coach, parent and platform. The code also has `interfaces/owner`, `interfaces/student`, `interfaces/public`, and the top-level modules `me_routes.py`, `registration_routes.py`, `magic_link_routes.py`, `unsubscribe_routes.py` and `email_webhook_routes.py` (`backend/v2/interfaces/`).
- [undocumented] README:14-21 `shared/` omits `comms/`, `profile/`, `scheduling/`, `security/`, `time/`, and the modules `caching.py`, `ids.py`, `money.py`, `names.py` and `occurrences.py`. The `http/` row says "error handlers, middleware", but it also holds `rate_limit.py`, `persona.py` and `client_ip.py`. `shared/observability/ops_digest.py` (modified here) is not covered by "OpenTelemetry + structured logs".
- [undocumented] README:24-29 tests omit `tests/composition`, `tests/contexts`, `tests/infrastructure`, `tests/shared`, `tests/seed`, `tests/fixtures`, and the top-level `test_no_raw_tenant_mongo_access.py` and `test_pytest_timeout_backstop.py`. `tests/structural` also holds policy and wiring tests beyond "layer-conformance + event-rules".
