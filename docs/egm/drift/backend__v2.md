## backend/v2/README.md

- [contract] README:103 says `pytest v2/tests` with >=70% coverage on `v2/shared`. `.github/workflows/production.yml:165` runs `--cov=v2` (the whole package) with `--cov-fail-under=86`.
- [contract] README:101 says mypy is `mypy --config-file backend/pyproject.toml v2` and advisory. `.github/workflows/production.yml:266-274` runs `mypy ... -p backend.v2` from the repo root, piped through `mypy-baseline filter`. The step is blocking at a frozen baseline, so new errors fail the build.
- [undocumented] README:59 lists the personas as `interfaces/{coach,parent,admin}/`. README:13 lists "admin, coach, parent, platform". The code also has `interfaces/owner/` (`main.py:3073-3074`, behind `enable_owner_role`), `interfaces/student/` (`main.py:3067-3072`, behind `enable_student_login`) and `interfaces/public/` (`main.py:3061-3062`). It also has top-level route modules (`interfaces/me_routes.py`, `magic_link_routes.py`, `password_reset_routes.py`, `email_webhook_routes.py`). `interfaces/platform/` is mounted only when `enable_platform_routes` is set (`main.py:3063-3064`), which the README does not mention.
- [undocumented] README:14-21 lists 7 `shared/` sub-packages. The code also has `shared/comms/`, `shared/profile/`, `shared/scheduling/`, `shared/security/` and `shared/time/`. It also has top-level modules `caching.py`, `ids.py`, `money.py`, `names.py` and `occurrences.py`. `shared/auth/` also holds `staff_tiers.py`.
- [undocumented] README:24-29 lists 5 test directories. The code also has `tests/composition/`, `tests/contexts/`, `tests/infrastructure/`, `tests/shared/`, `tests/seed/` and `tests/fixtures/`. It also has top-level `test_no_raw_tenant_mongo_access.py` and `test_pytest_timeout_backstop.py`.
- [undocumented] README:5-30 omits the `composition/` package (about 90 wiring modules, for example `composition/admin.py`). It is a sibling of `contexts/` and holds most of the wiring that the "composition root" description (README:30, 53) attributes to `main.py`. `main.py` is about 3,400 lines but delegates to `composition/`. `backend/v2/tests/structural/test_composition_is_wiring.py` guards this.
- [wording] README:53 says to "Wire the context into the composition root in `main.py`". Context wiring lives in `composition/<name>.py` modules (`composition/` listing), and `main.py` only mounts routers (`main.py:3055-3074`).
- [wording] README:30 labels `main.py` "composition root" only. The layout does not list the `composition/` layer, as noted above.
- [wording] README:48 says each context has `domain/events.py`. The canonical Identity example README:55 has no `contexts/identity/domain/events.py`. Its domain files are `models.py`, `errors.py` and others. README:46 and README:49 prescribe `application/use_cases/` and `application/ports.py`. Identity has both, but also many flat `*_use_case.py` modules in `application/`.
- [wording] README:12 lists the contexts as "identity, enrollment, coaching, billing, etc." The actual contexts are: ai, billing, coaching, communications, crm, curriculum, enrollment, finance, identity, onboarding, platform, student_progress. Nothing in the README is wrong, but the list is incomplete.
- [wording] README:3 links to `../../../.claude/plans/write-a-detailed-plan-curried-trinket.md`. That path does not exist in the repo, so the link is dead for anyone without the author's local plan file.
- [wording] README:42 says ADR-0005 has "six layer rules". `docs/adr/0005-clean-architecture-lite-monolith.md` has a "Layering Rules (enforced)" section at line 34. Its action item at line 125 also says six. I did not count the rules in `backend/pyproject.toml:69+`, so the number is unverified.
- [wording] README:36-39 shows the layer diagram as `interfaces -> application -> domain`. The `interfaces/` tree contains persona `views.py` and `*_routes.py` files, and `main.py` imports them directly. This is a diagram simplification, not a code mismatch.
