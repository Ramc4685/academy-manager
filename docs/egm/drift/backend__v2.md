- [wording] README:101 calls mypy "advisory in the backend lint job" with `mypy --config-file backend/pyproject.toml v2`. Actual step is blocking at a frozen baseline: `mypy --config-file backend/pyproject.toml -p backend.v2` filtered by `mypy-baseline` (`.github/workflows/production.yml:266-274`).
- [wording] README:100 lists only `ruff` (lint). CI also runs `ruff format --check v2` (`production.yml:262-264`).
- [missing] README:12,59 lists personas "admin, coach, parent, platform" (BFF choices: coach/parent/admin). `backend/v2/interfaces/` also has `owner/`, `student/` and `public/`, plus top-level route modules (`me_routes.py`, `registration_routes.py`, `magic_link_routes.py`, `password_reset_routes.py`, `unsubscribe_routes.py`, `email_webhook_routes.py`), all mounted at `backend/v2/main.py:3055-3074`. Some are conditionally mounted (platform at `main.py:3064`, student at `main.py:3072`, owner at `main.py:3074`).
- [missing] README:10-31 layout omits `backend/v2/composition/` (about 90 wiring modules), `shared/security`, `shared/comms`, `shared/profile`, `shared/scheduling`, `shared/time` and the top-level `shared/*.py` helpers (`money.py`, `ids.py`, `occurrences.py`, `names.py`, `caching.py`). Also omitted are `tests/{composition,contexts,infrastructure,shared,fixtures,seed}`.
- [undocumented] README:22 says migrations are "idempotent boot migrations". The code is a runner/CLI invoked as `python -m backend.v2.migrations` (`backend/v2/migrations/__main__.py`, `cli.py`, `runner.py`), and deploy runs it separately (`production.yml:886,952`). The README does not mention this entry point.
- [missing] README:12 lists contexts "identity, enrollment, coaching, billing, etc.". Actual contexts include `ai`, `communications`, `crm`, `curriculum`, `finance`, `onboarding`, `platform` and `student_progress` (`backend/v2/contexts/`). Some have their own READMEs, but the top-level list omits them.
- [contract] README:48 says every context has `domain/events.py` and README:46-49 prescribes `domain/{models,events,errors}.py` plus `application/use_cases/` and `ports.py`. The "canonical example" identity context (README:55) has no `domain/events.py` (`backend/v2/contexts/identity/domain/`). It also puts many use cases directly in `application/*.py` rather than only `use_cases/`. Several contexts (ai, crm, communications, finance, identity, platform) also lack `domain/events.py`.
- [wording] README:54-55 says "The Identity context built in W1A-02 is the canonical example". Identity has grown far past that shape (see `backend/v2/contexts/identity/`), so it is a poor template.
- [wording] README:36-40 layer diagram and README:42 "six layer rules" vs `backend/pyproject.toml:79-139`, which are separate import-linter contracts (domain-is-pure, application-does-not-import-infrastructure, infrastructure-does-not-import-interfaces, interfaces-do-not-import-infrastructure-or-domain-directly, and others). The README's linter rules (README:33) and tenancy claim (README:102 "layer rules + tenancy") were not individually verified as matching.
- [wording] README:78 `lint-imports --config backend/pyproject.toml` from repo root, while CI runs it from `backend/` as `lint-imports --config pyproject.toml` (`production.yml:159`). Both forms are documented elsewhere in the README (README:87), so this is minor.
