## backend/v2/README.md

- [contract] README L14-L21 lists `shared/` as auth, config, events, http, idempotency, observability, tenancy. Code adds undocumented packages `shared/comms/`, `shared/profile/`, `shared/scheduling/`, `shared/security/` and `shared/time/`, plus top-level modules `caching.py`, `ids.py`, `money.py`, `names.py` and `occurrences.py` (backend/v2/shared/).
- [undocumented] README L8-L30 Layout omits `composition/` (backend/v2/composition/, about 100 wiring modules that `main.py` uses). The import-linter config forbids `shared` from importing it (backend/pyproject.toml:~186).
- [contract] README L13 and L59 name the personas as admin, coach, parent, platform. Code also has `interfaces/owner/`, `interfaces/student/` and `interfaces/public/` (backend/v2/interfaces/, mounted at backend/v2/main.py:3071-3083). `student` and `owner` are behind the flags `enable_student_login` and `enable_owner_role`. `platform` is behind `enable_platform_routes` (main.py:3072). README L6 says all routes are mounted unconditionally. Several non-persona route files also sit at the `interfaces/` root (`me_routes.py`, `registration_routes.py`, `magic_link_routes.py` and others).
- [wording] README L24-L29 lists five test dirs. `tests/` also has `composition/`, `contexts/`, `infrastructure/`, `shared/`, `seed/` and `fixtures/`, plus top-level structural tests such as `test_no_raw_tenant_mongo_access.py` (backend/v2/tests/).
- [wording] README L27 says contract tests use "mongo + stripe via testcontainers". No `testcontainers` reference exists in backend/v2/tests. Contract tests use a real or mock Mongo with uuid-named databases (tests/contract/conftest.py:28,113). The CI job `backend-contract-real-mongo` runs them against a native mongod 8.0 (.github/workflows/production.yml:167-227).
- [wording] README L29 says `structural/` holds "layer-conformance + event-rules checks". It actually holds many policy and parity tests, such as persona gates, openapi snapshot and route-duplicate checks (tests/structural/). No event-rules test is evident.
- [stale-not-built] README L12 and L48 say each context has `domain/models.py`, `domain/events.py` and `domain/errors.py`. `contexts/communications/domain/` lacks `events.py`, and `contexts/finance/domain/` has none of the three (backend/v2/contexts/). `contexts/platform` is split into `audit/`, `billing/` and `governance/` subcontexts, and `contexts/curriculum/` has a `content/` dir.
- [contract] README L46-L47 and L51 describe `contexts/<name>/{domain,application,infrastructure}` only. Nested contexts (`contexts/platform/{audit,billing,governance}`) exist and the import-linter rules carry `*.*` variants for them (backend/pyproject.toml:~90-110).
- [undocumented] README L49 says use cases live in `application/use_cases/`. The identity context, which README L55 names as canonical, keeps most use cases as flat `*_use_case.py` files directly in `contexts/identity/application/`. `use_cases/` there holds only `admin_directory.py` and `bootstrap_academy.py`.
- [stale-not-built] README L63 says each persona has `interfaces/<persona>/views.py`. `interfaces/platform/` has no `views.py` (admin, coach, parent and student do). Admin also splits views across `*_views.py` files.
- [stale-not-built] README L65 says to "Add a negative test asserting wrong-persona returns 404". The structural tests are persona-gate policy tests (tests/structural/test_persona_gate_is_called.py, plus the comment at tests/interface/conftest.py:976 saying the old "admin gets 404 on coach routes" tests no longer fit).
- [contract] README L103 says pytest has "≥70% coverage on `v2/shared`". CI enforces `--cov=v2 --cov-fail-under=86` over all of v2 (.github/workflows/production.yml:165).
- [contract] README L101 says mypy is `mypy --config-file backend/pyproject.toml v2`, "advisory". CI runs `mypy --config-file backend/pyproject.toml -p backend.v2` filtered by `mypy-baseline` (new errors fail) (production.yml:268-274).
- [wording] README L100-L103 gives `ruff (lint)` only. CI also runs `ruff format --check v2` (production.yml:264), and runs `compileall`, a separate contract-test job and a pip-audit step.
- [wording] README L42 and L33 describe six layer rules and a tenancy check. Rule 6 (academy_id literals) is not an import-linter contract. pyproject.toml says it is enforced by `tests/structural/test_tenancy_literals.py`, which does not exist in backend/v2/tests/structural. - [wording] README L22 says "idempotent boot migrations". The code has 154 numbered files (backend/v2/migrations/), with no boot-time trigger evident in `main.py` or `shared/config/settings.py` (searched for V2_RUN_MIGRATIONS_ON_BOOT, no match).
- [wording] README L23 says `scripts/` holds operator CLIs "(e.g., replay_event.py)". It also holds `reconcile_membership_roles.py`. This is minor.
